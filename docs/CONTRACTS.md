## 1. UI ↔ Agent WebSocket Protocol (`events.ts`)

- **Endpoint:** `ws://127.0.0.1:7777`
- **Authentication:** Per-launch token (`PENGU_WS_TOKEN` or cryptographically random 32-byte hex generated by `services/agent` on startup). Supplied via `Authorization: Bearer <token>` header or `?token=<token>` query string during the WebSocket upgrade handshake. Rejected connections receive HTTP `401` and are never upgraded. Never hardcode this token in the frontend bundle.
- **Framing:** UTF-8 JSON objects with a discriminated `type` field.

### 1.1 Client → Server Messages

| `type` | Payload | Purpose |
|---|---|---|
| `user.message` | `{ taskId?: string, text: string, source: "text" \| "voice" }` | Start a new task or continue an active conversation. |
| `approval.decision` | `{ approvalId: string, decision: "approve" \| "deny" }` | Relay the user's explicit decision for a pending consequential action. |
| `task.list.request` | `{ filter?: "pending" \| "all" }` | Request persisted tasks for Startup Restore (`"pending"`) or History (`"all"`). |
| `task.resume` | `{ taskId: string }` | Trigger Section 7.6 restart-safe resume for a pending/paused task. |
| `task.cancel` | `{ taskId: string }` | Cancel a running, paused, or pending task. |
| `voice.audio` | `{ mime: string, base64: string, languageHint?: string }` | Send recorded microphone audio to M3's Saaras STT route. |
| `tts.request` | `{ text: string, language: string }` | Request spoken audio via M3's Bulbul TTS route. |

### 1.2 Server → Client Events

| `type` | Payload | Purpose |
|---|---|---|
| `task.created` | `{ taskId: string, request: string }` | Emitted immediately when a new task is accepted and persisted. |
| `task.step` | `{ taskId: string, stepId: string, tool: string, server: string, kind: "read" \| "routine" \| "consequential", status: "planned" \| "running" \| "awaiting_approval" \| "done" \| "failed" \| "skipped", summary: string }` | Live execution timeline update. Never includes private chain-of-thought or secrets. |
| `approval.requested` | `{ approvalId: string, taskId: string, preview: ApprovalPreview, reason: string, expiresAt: string }` | Pauses a consequential step and sends the exact reviewable preview to `ApprovalModal`. |
| `approval.invalidated` | `{ approvalId: string, reason: string }` | Sent when a pending approval expires, is superseded, or its underlying target (e.g., draft content) changes. |
| `task.finished` | `{ taskId: string, status: "completed" \| "partial" \| "failed" \| "cancelled" \| "paused", summary: string, unresolved: string[] }` | Honest terminal or paused outcome. `"completed"` is emitted **only** after verification. |
| `task.list` | `{ tasks: TaskSummaryItem[] }` | Sanitized task summaries for History and Startup Restore (no secrets, no raw private email bodies). |
| `pet.state` | `{ state: "idle" \| "listening" \| "thinking" \| "executing" \| "awaiting_approval" \| "completed" \| "failed" }` | Simple companion visual state indicator. |
| `voice.transcript` | `{ text: string, language: string }` | Result of `voice.audio` transcription; UI shows transcript before any consequential execution. |
| `tts.audio` | `{ mime: string, base64: string }` | Synthesized speech audio in a verified supported language. |
| `tts.unsupported` | `{ reason: string }` | Explicit refusal when the requested TTS language/voice is unsupported. |
| `error` | `{ code: string, message: string }` | Structured protocol or runtime error. |

### 1.3 Minimum `TaskSummaryItem` Shape (`task.list.tasks[]`)

```ts
{
  taskId: string;
  request: string;
  status: TaskState;
  steps: Array<{
    stepId: string;
    summary: string;
    tool?: string;
    server?: string;
    status: StepStatus;
  }>;
  pauseReason?: string;
  updatedAt?: string;
  outputRefs?: Record<string, string>; // e.g. { draftId: "...", folderPath: "..." }
}
```

### 1.4 `ApprovalPreview` Shape

```ts
{
  title: string;
  account?: string;
  recipient?: string;
  subject?: string;
  body?: string;
  command?: string;
  commandId?: string;
  args?: Record<string, unknown> | string[];
  cwd?: string;
  purpose?: string;
  impact: string;
  reversible: boolean;
}
```

For shell approvals, `commandId`, `args`, `cwd`, `purpose`, `impact`, and `reversible` are mandatory. For email send approvals, `account`, `recipient`, `subject`, `body`, `impact`, and `reversible` are mandatory. The UI never computes risk or constructs approval tokens.

## 2. Tool Manifest & Untrusted Content Contract (`tools.ts`)

Every MCP server ships `tool-manifest.json` at its package root. M1's `McpToolRegistry` loads these manifests at startup and **denies by default** any tool with a missing manifest entry or unknown risk class.

Per tool entry:
- `name`: canonical tool ID
- `description`: human-readable summary
- `riskClass`: `"READ" | "ROUTINE" | "CONSEQUENTIAL"`
- `scope`: required setup permission (e.g., `"gmail:read"`, `"gmail:compose"`, `"gmail:send"`, `"fs:approved_roots"`, `"browser:http_https"`, `"app:allowlist"`, `"shell:allowlist"`)
- `sideEffect`: `boolean`
- `idempotent`: `boolean`
- `reversible`: `boolean`
- `previewTool?`: READ tool invoked by M1 before requesting approval
- `requiresApprovalToken`: `boolean`

### Canonical Tool Matrix

| Server | Tool | Risk Class | Side Effect | Preview Tool | Approval Token |
|---|---|---|---|---|---|
| `gmail` (M3) | `gmail_search_threads` | `READ` | `false` | — | `false` |
| `gmail` (M3) | `gmail_read_thread` | `READ` | `false` | — | `false` |
| `gmail` (M3) | `gmail_create_draft` | `ROUTINE` | `true` | — | `false` |
| `gmail` (M3) | `gmail_get_draft` | `READ` | `false` | — | `false` |
| `gmail` (M3) | `gmail_send_draft` | `CONSEQUENTIAL` | `true` | `gmail_get_draft` | `true` |
| `local` (M4) | `fs_list_dir` | `READ` | `false` | — | `false` |
| `local` (M4) | `fs_create_folder` | `ROUTINE` | `true` | — | `false` |
| `local` (M4) | `browser_open_url` | `ROUTINE` | `true` | — | `false` |
| `local` (M4) | `app_launch` | `ROUTINE` | `true` | — | `false` |
| `local` (M4) | `shell_describe_command` | `READ` | `false` | — | `false` |
| `local` (M4) | `shell_run_restricted` | `CONSEQUENTIAL` | `true` | `shell_describe_command` | `true` |

### Untrusted Data Wrapper

Any tool returning external content (email bodies, attachments, web pages, external files) **must** wrap it as:

```json
{
  "untrusted": true,
  "source": "gmail_read_thread",
  "content": "..."
}
```

M1's prompt builder places all `untrusted: true` payloads inside an explicit data-only delimiter block and enforces that untrusted content can never grant permissions, alter recipients, request tools, or initiate tasks.

## 3. Approval Token Contract (`approval.ts`)

1. **Canonical JSON (`canonicalJSON`):** Object keys sorted lexicographically (recursive), arrays preserved in order, compact JSON (no insignificant whitespace), `undefined` object properties omitted.
2. **`argsHash`:** `sha256(canonicalJSON(resolvedArgs))` as lowercase 64-char hex.
   - For `gmail_send_draft`: `resolvedArgs = { draftId, contentHash }`, where `contentHash = sha256(`${to}|${subject}|${body}`)` of the draft **as currently stored**.
   - For `shell_run_restricted`: `resolvedArgs = { commandId, args, cwd }` using the validated allowlisted `commandId`, validated arguments, and resolved working directory.
3. **Token Payload:** `{ approvalId, tool, argsHash, expiresAt }` where `expiresAt` is an ISO-8601 UTC timestamp (default TTL: 180 seconds).
4. **Signature:** `HMAC-SHA256(PENGU_APPROVAL_SECRET, canonicalJSON(payload))` as lowercase hex.
5. **Server-Side Injection:** M1 attaches the signed token under the reserved MCP call field `__pengu_approval` (`RESERVED_APPROVAL_TOKEN_FIELD`). This field is **stripped from all model-visible tool schemas**, rejected if supplied by the LLM, and **never sent to the desktop UI**.
6. **Independent Server Verification:** `mcp/gmail` and `mcp/local` independently re-fetch/re-resolve the live action, recompute `argsHash`, verify the HMAC using constant-time comparison (`crypto.timingSafeEqual`), check `Date.now() < Date.parse(expiresAt)`, and **refuse** on any mismatch.
7. **No Cross-Restart Reuse:** Approval tokens live only in agent memory and are never persisted or reused across app/laptop restarts.

## 6. Resume Contract (Section 7.6)

1. On startup, UI sends `task.list.request { filter: "pending" }`.
2. User chooses **Continue** (`task.resume`), **Cancel** (`task.cancel`), or **Leave pending**.
3. On `task.resume { taskId }`, M1's `TaskResumer` executes in strict order:
   1. Verify required MCP servers are up and Gmail OAuth token / local scopes are still valid.
   2. Load latest checkpoint and all receipts/side-effect records from M4's store.
   3. For each step with a `completed` side-effect record/receipt: **trust the receipt and skip** (never repeat).
   4. For any `begun-but-not-completed` side effect: run the tool's verifier (`verifyDraftSent`, `verifyFolderExists`, etc.).
      - If verified `completed`: record completion receipt and skip.
      - If verified `not_executed`: re-queue cleanly (with fresh approval if consequential).
      - If `unknown` (indeterminate external operation, e.g., browser URL / app launch or network timeout during send): **pause and ask the user**; never retry blindly.
   5. Any not-yet-executed `CONSEQUENTIAL` step requires a **fresh** approval preview and HMAC token.
